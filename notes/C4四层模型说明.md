# C4 模型四层说明

## 什么是 C4
C4 = **Context / Container / Component / Code**，由 Simon Brown 提出，用"由粗到细、逐层放大"的方式描述软件架构。像地图缩放：先看全局，再逐层放大看细节。
核心思想：**一份模型，多个层级视图**——不是每层各画一张互不相干的图，而是同一份模型从不同粒度去看。

## 四个层级

### 1. 系统上下文 Context（最粗）
- **看什么**：把整个系统当成一个黑盒，画出它和谁打交道——**用户/角色**、**外部系统**。
- **回答**：这个系统是干什么的？谁在用？依赖哪些外部系统？
- **元素**：软件系统（本系统）、用户/角色、外部系统。
- **例**：`顾客` → 使用 → `在线书店`；`在线书店` → 调用 → `第三方支付平台`。

### 2. 容器 Container（放大一层）⭐微服务拆分主战场
- **看什么**：打开系统黑盒，看里面**可独立部署/运行的单元**及其交互。
- **注意**：C4 的"容器"**不是 Docker 容器**，而是"应用 / 数据存储"这一级——
  **微服务、Web 应用、API 网关、数据库、消息中间件、缓存、对象存储**都算容器。
- **回答**：系统由哪些微服务/存储/中间件组成？它们之间怎么通信（同步/异步）？
- **本工具的"微服务基础设施"元素（网关/MQ/DB/缓存/对象存储/Saga）都在这一层。**

### 3. 组件 Component（再放大）
- **看什么**：打开**某一个容器（微服务）**，看它内部的**主要模块/构件**及其关系。
- **回答**：这个微服务内部怎么分层/分模块？
- **典型构件**：API 控制器、应用服务、领域模型/聚合、仓储（对应 DDD 战术设计）。

### 4. 代码 Code（最细）
- **看什么**：打开**某一个组件**，看它的**类/接口**级实现（通常是 UML 类图，多为自动生成）。
- **实践中经常省略**——太细、易过时、维护成本高。C4 官方也建议按需才画。

## 层级之间的归属关系
```
软件系统 ⊃ 容器（微服务） ⊃ 组件 ⊃ 代码
```
- 一个**系统**包含多个**容器（微服务）**；
- 一个**容器**包含多个**组件**；
- 一个**组件**包含多个**代码**元素。

本工具用 `parentSystem` / `parentContainer` / `parentComponent` 字段记录归属。

## 一份模型，多个视图（重要）
- **切换层级 = 换视角过滤，不改数据、不丢内容。**
- **项目 = 一份完整模型**，包含所有层级的全部元素与关系；层级只决定当前画布显示哪一层。
- 保存项目存整份模型，打开项目全部还原。

## 本工具现状与增强方向
- **现状**：按元素类型过滤显示每一层；内置示例主要建在"容器"层。
- **待增强**：
  1. 示例补齐 系统 → 容器 → 组件 → 代码 的完整归属与跨层关系；
  2. **下钻导航**：双击系统进入其容器视图、双击容器进入其组件视图，配面包屑返回——让四层真正可导航。
